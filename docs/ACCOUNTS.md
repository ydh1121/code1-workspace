# CODE1 계정과 농가별 권한

## 사용할 계정

| 계정 종류 | 농가 자료 | 아자몰 제안서 | 계정 관리 |
|---|---|---|---|
| 최고 관리자 — 소유자 본인 | 전체 보기·입력·업로드·검토 | 전체 보기·편집·저장·PDF | 서브 관리자와 농가 계정 발급·권한 변경·접근 중지 |
| 서브 관리자 — 농가 관리자 | 최고 관리자와 같은 전체 업무 권한 | 최고 관리자와 같은 전체 업무 권한 | 농가 계정 발급·권한 변경·접근 중지 |
| 농가 계정 | 선택한 농가만. 숨김 / 보기만 / 입력·업로드·제출 | 숨김 / 보기·PDF / 편집·저장·PDF | 본인 비밀번호 변경 |

최고 관리자 계정은 다른 계정에서 바꾸거나 중지할 수 없습니다. 서브 관리자는 관리자 계정의 권한을 바꿀 수 없습니다. 실제 두 번째 사용자의 이름·아이디·비밀번호는 관리자가 화면에서 지정하며 코드에 임의 계정을 넣지 않았습니다.

계정별 페이지와 농가 범위는 서버에서 매 요청 다시 읽습니다. 권한 변경·접근 중지·비밀번호 재설정 시 기존 로그인은 해제됩니다. 숨긴 제안서와 미지정 농가의 이름·제출 내용·사진은 브라우저로 내려보내지 않습니다. 이미 사용자가 내려받거나 보았던 자료를 소급 삭제하는 기능은 아닙니다.

## 이미 배포한 사이트에 이번 변경 적용

사이트는 `https://code1-workspace.pages.dev`입니다. GitHub main 반영과 **Google 데이터 연결 코드 적용**은 서로 다른 단계입니다. 이번 계정 코드를 적용하려면 아래 작업이 필요합니다. 새 Cloudflare 프로젝트·DB·Apps Script 프로젝트는 만들지 않습니다.

### 1. 비밀번호 보호 키 한 개 추가

1. Cloudflare에서 **Workers 및 Pages → code1-workspace → 설정(Settings) → 변수 및 시크릿(Variables and Secrets)**을 엽니다.
2. **Production → 추가(Add)**를 누릅니다.
3. 이름에 `PASSWORD_PEPPER`를 입력합니다.
4. 유형은 **Secret**을 선택합니다. 값에는 비밀번호 관리자로 생성한 **32자 이상 무작위 문자열**을 입력합니다. 기존 `SESSION_SECRET`, `BRIDGE_SECRET`과 다른 값입니다.
5. 저장합니다. 기존 6개 환경값은 유지합니다. 모든 값을 Secret으로 등록해도 됩니다.

이 키는 비밀번호의 서버 검증에 사용합니다. 나중에 임의로 바꾸면 기존 아이디 로그인에 비밀번호 재설정이 필요합니다. Google 최고 관리자 복구 로그인은 유지됩니다. 실제 값은 채팅이나 GitHub에 올리지 않습니다.

### 2. 기존 Apps Script 연결 파일 두 개 적용

1. [기존 CODE1 Apps Script 편집기](https://script.google.com/d/1AoMVWNQIsUxIQc7QjBoHkKPWGgPhOiLWdxFlTYnCWe2t8eFbtmHfavrb/edit)를 엽니다.
2. 왼쪽 **편집기 (`<>`)**를 누릅니다.
3. **CloudflareBridge.gs**를 클릭하고 [최신 CloudflareBridge.gs](../bridge/CloudflareBridge.gs)의 내용 전체로 교체합니다.
4. **파일 옆 + → 스크립트**를 누릅니다. 이름을 **AccessControl**로 입력합니다.
5. 자동 생성된 내용을 지우고 [AccessControl.gs](../bridge/AccessControl.gs)의 전체 코드를 붙여넣습니다. 이미 있으면 기존 파일 내용을 교체합니다.
6. **Ctrl+S**로 저장합니다. `Server`, `Auth`, `Media`, `Deck`, 원본 자산 파일은 유지합니다. 예전 전체 설치 함수를 실행하지 않습니다.
7. 오른쪽 위 **배포 → 배포 관리**를 누릅니다.
8. 왼쪽 목록에서 **Cloudflare 데이터 연결** 배포를 선택합니다. 현재 URL의 배포 ID는 `AKfycbx1FJr3BfX3DgfYnMmKDFHzZBxoO8NPlWZ4y9I3M68X8UYoptIFoBhL1ufOzoCwInl7`입니다.
9. **수정(연필) → 버전 → 새 버전**을 선택합니다. 설명에 `계정과 농가별 권한`을 적습니다.
10. 기존 **실행: 나 / 액세스: 모든 사용자**를 유지하고 **배포**를 누릅니다. 기존 `/exec` URL이 유지되므로 `BRIDGE_URL`을 바꾸지 않습니다.

### 3. Cloudflare 환경값 적용 후 최초 최고 관리자 로그인

1. Cloudflare **code1-workspace → 배포(Deployments)**에서 main 최신 코드의 **… → 배포 다시 시도(Retry deployment)**를 누릅니다. 새 비밀값이 적용된 배포가 성공했는지 확인합니다.
2. 사이트를 새로고침하고 **최고 관리자 Google 로그인**을 누릅니다.
3. 반드시 `master.solly.art@gmail.com`을 선택합니다. Google OAuth 클라이언트·리디렉션 URI는 기존 설정을 재사용합니다.
4. 인증된 소유자가 처음 들어올 때만 아래 CODE1 계정 전용 탭과 최고 관리자 한 명을 생성합니다. 기존 농가·제안서·Drive 원본은 이동하거나 복사하지 않습니다.
5. **계정 관리 → 내 로그인 정보**에서 새 비밀번호와 확인 값을 입력하고 **내 비밀번호 저장**을 누릅니다. 최초 최고 관리자 아이디는 `owner`입니다.
6. 이후에는 아이디와 비밀번호로 로그인할 수 있습니다. 최고 관리자가 비밀번호를 잊으면 **최고 관리자 Google 로그인**으로 들어온 뒤 5분 안에 현재 비밀번호를 생략하고 새 비밀번호를 저장할 수 있습니다.

최초 설정은 예전 `14_WEB_설정`의 `ALLOWED_USER_2`를 공란, `CONTRIBUTOR_DECK_EDIT`을 `FALSE`로 전환합니다. 예전 Apps Script 주소의 이메일 허용 목록을 통해 새로운 농가 제한을 우회하지 못하도록 하는 조치입니다. 기존 두 번째 사용자가 있다면 아래에서 계정을 새로 발급하세요. OWNER와 정본 데이터 설정은 유지합니다.

## 서브 관리자 추가

1. **계정 관리 → 계정 추가**를 누릅니다.
2. 사용자 이름, 로그인 아이디, 12자 이상 비밀번호를 입력합니다.
3. **계정 종류 → 서브 관리자 · 전체 자료**를 선택합니다.
4. **사용 상태 → 사용 가능 → 계정과 권한 저장**을 누릅니다.
5. **로그인 링크 복사**를 누르고 아이디·비밀번호를 담당자에게 직접 안내합니다. 앱이 외부에 연락하거나 초대를 자동 전송하지는 않습니다.

서브 관리자는 별도 Google 계정 등록이나 Google 테스트 사용자 추가 없이 ID·비밀번호로 로그인합니다.

## 농가에 직접 입력을 맡길 때

1. 먼저 **농가 자료**에서 해당 농가의 자료를 임시저장합니다. 농가 목록에 나타나야 배정할 수 있습니다.
2. **계정 관리 → 계정 추가**에서 이름·아이디·비밀번호를 입력합니다.
3. **계정 종류 → 농가 계정 · 지정한 자료만**을 선택합니다.
4. **농가 자료 → 입력·업로드·제출 가능**, **아자몰 제안서 → 숨김**을 선택합니다.
5. **보여줄 농가 선택**에서 이 계정이 담당할 농가만 체크합니다.
6. **계정과 권한 저장 → 로그인 링크 복사** 후 해당 농가에 직접 안내합니다.

보기만 필요하면 농가 자료를 **보기만**으로 바꿉니다. 업무가 끝나면 계정의 **권한·계정 수정 → 사용 상태 → 접근 중지 → 저장**을 누릅니다. 비밀번호를 잊은 농가 계정은 같은 수정 창에서 새 비밀번호를 지정합니다. 비밀번호 칸이 공란이면 현재 비밀번호를 유지합니다.

농가 계정은 지정된 농가의 기존 작성 내용을 이어서 입력할 수 있습니다. 다른 농가 생성, 제출 승인, 정본 반영 처리, Drive 파일 ID 연결은 관리자 업무입니다. 이미 승인된 자료는 기존 규칙대로 잠기며 관리자에게 후속 작성 자료를 요청해야 합니다.

## 저장과 구현 범위

- 기존 CODE1 Google Sheet에만 `19_WEB_ACCOUNTS`, `20_WEB_ACCESS_LOG`, `21_WEB_LOGIN_GUARD`를 추가합니다. 충돌하는 기존 헤더가 있으면 덮어쓰지 않고 중단합니다.
- 계정 행에 ID, 표시 이름, 역할, 활성 상태, 메뉴별 허용 수준, 배정 농가 ID, 비밀번호 검증값, 세션 버전을 저장합니다. 권한과 세션 버전은 한 행으로 함께 저장됩니다.
- 실제 비밀번호는 저장하지 않습니다. 서로 다른 salt와 PBKDF2-SHA256 100,000회, Cloudflare에만 있는 별도 pepper를 사용합니다. 비밀번호·해시·쿠키는 계정 목록과 로그에 포함하지 않습니다.
- 동일 ID는 15분에 8회, 동일 접속 IP는 15분에 40회까지 로그인을 시도할 수 있습니다. 제한은 Sheet에 저장되어 실행 서버가 바뀌어도 유지됩니다. 로그인과 계정 변경 이력을 기록합니다.
- 참고 India 프로젝트의 자체 ID 로그인·관리자 계정 발급 방식을 CODE1에 맞춰 적용했습니다. 해당 프로젝트의 계정·비밀번호·문서·DB를 복사하거나 연결하지 않았습니다. 기기 등록/대수 제한 기능은 이번 범위에 포함하지 않습니다.
- 기존 정본 00~10, 질문카탈로그, 농가 제출·미디어 큐, 제안서 저장 형식과 `STAGING_ONLY`는 그대로 사용합니다. 새 비밀값은 GitHub에 커밋하지 않습니다.

## 적용 후 실제 확인할 항목

실제 최고 관리자 로그인, 새 서브 관리자 로그인과 전체 업무, 서로 다른 두 농가 계정의 목록·직접 요청·사진 접근 분리, 보기 전용 저장 차단, 권한 변경 후 기존 로그인 차단, 실제 저장/업로드/제출 및 PDF를 확인합니다. 저장소 자동검증은 이 실사용 검증을 대신하지 않습니다.
